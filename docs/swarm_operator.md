## 0. 一句话结论

`SwarmMutation_310` 是 gpevo **自创**的「分子感知刚体引导算子」，不是 MATLAB USPEX
PSO 模块的移植，也不是教科书 PSO：它没有速度 / 惯性、没有个体历史最优 pbest，
本质是「把父代分子朝**当代**最优结构的对应分子做 0~50% 随机插值，再叠加 ±30°
随机刚体旋转」。

对分子晶体：**结构上安全**（只做刚体变换，不撕分子，有合法性门），但**作为全局
搜索算子收益有限**。原有实质缺陷「引导位移用父代晶胞折叠、却拿最优结构的笛卡尔
质心作目标」（晶胞不对齐，见 §5.2 B）**已修复**，配对也补了 `MtypeLIST` 断言（§5.2 A）。
默认 `fracSwarm = 0` 关闭、且是额外配额，是合理的保守设计。

## 1. 定位：为什么不是移植 MATLAB 的 PSO

`SwarmMutation_310.py:1-24` 的模块 docstring 明确说明。MATLAB 侧
`/home/feng/uspex-gp/FunctionFolder/PSO/` 是**原子级** PSO：

- `Random_PSO.m` 逐原子随机放置（`candidate = rand(sum(numIons), 3)`）；
- `Mutation_PSO.m` 沿软模逐原子位移；
- `PSO.m:101-104` 用指纹余弦距离算三个概率
  `P_p = rand*PSO_BestEver*dist1`（个体历史最优）、
  `P_g = rand*PSO_BestStruc*dist2`（全局最优）、
  `P_m = rand*PSO_softMut`（软模）。

逐原子操作会把分子撕开，因此**不支持分子体系（calculationType 310）**。gpevo 的
swarm 把作用单位换成整个分子，是对 PSO「向最优靠拢 + 随机步长」这一**思想**的
重新实现，不是代码移植。

## 2. 算法逐行

`SwarmMutation_310(count)` 产一个子代，最多 50 次 attempt：

| 步骤 | 代码 | 内容 |
|---|---|---|
| 取引导点 `g` | `SwarmMutation_310.py:88-96` | `best = POP.POPULATION[ranking[0]]`，`ranking` 来自 `valid_ranking(POP)`（`variation_common.py:70-83`，上一代 `FitnessRankingCorrection` 的结果，注释自述可能 stale）。`g` 是**当代**最优，不是 ever-best |
| 目标质心 | `:115` | `targets = _centers(best)`，`_centers` = 每个 `MOLCOORS.mean(0)`（`:75-77`） |
| 配对 | `:103-116` | 仅检查 `len(child.MOLECULES) == len(best.MOLECULES)`，然后按**位置索引** `position` 把父代第 i 个分子配到 `targets[i]`。当前实现下两侧 `MtypeLIST` 恒按类型分组（见 §5.2 A），故类型层面对齐；现已加 `MtypeLIST` 一致性断言 |
| 位移 | `:119-120` | `delta = _min_image(targets[i], center, lattice, best.LATTICE)`；`new_center = center + U(0, step)*delta`，`step = swarmStep` 默认 0.5 |
| 最小镜像 | `:41-73` | `target` 先按 `best.LATTICE` 转分数、再映射回 child 晶胞，然后 `frac = delta @ inv(lattice)`；`frac -= np.round(frac)`；再转回笛卡尔（半偶舍入，与 `newMolCheck` 一致） |
| 刚体平移 | `:122` | `coords = coords + (new_center - center)` |
| 刚体旋转 | `:123-125` | 随机轴 `randn(3)`，随机角 `U(-angle_max, angle_max)`，`angle_max = swarmAngle` 默认 30°；经 `Rotate_rigid_body`（Rodrigues 行向量形式） |
| 合法性门 | `:130-131` | `valid_molecules(child, -0.2)`，不过则 `continue` |
| 收尾 | `:132-137` | `recompute_zmatrix` → `finalize_offspring(child, "Swarm")` → append，打印 `generated by swarm mutation (attempt N)` |
| 兜底 | `:139-141` / `:89-94` | 50 次全败、或没有 ranking，回退 `Random_310` |

写成公式（第 i 个分子，`x_i` 为质心，`g_i` 为最优结构第 i 个分子质心）：

```
g_frac    = g_i @ inv(L_best)                     # 最优结构的分数坐标
g_child   = g_frac @ L_parent                    # 映射到 child 参考系
x_i <- x_i + U(0, 0.5) * min_image(g_child - x_i, L_parent)
R_i <- Rodrigues(randn(3), U(-30deg, 30deg))
coords_i <- (coords_i - x_i) @ R_i + x_i          # 分子内几何逐位不变
```

要点：

- **只动 `MOLCOORS`，晶胞 `LATTICE` 不变**（`:114` 的 `lattice` 只用于最小镜像折叠）。
  注释说「交给后续弛豫」，但弛豫是局部优化，不会跨到另一个晶胞盆地。
- 所有操作都是刚体变换 → 分子内键长 / 键角**逐位不变**，这是它相对原子级 PSO
  的核心优势，也是它能用于分子晶体的前提。
- `U(0, step)` 是**收缩**（最多朝 `g` 走一半），不是外推；没有速度、没有惯性权重、
  没有认知项（pbest），随机性是唯一的探索来源。

## 3. 三方对照

| | 教科书 PSO | MATLAB USPEX PSO | gpevo swarm |
|---|---|---|---|
| 作用单位 | 连续向量 | **原子**坐标 | **整个分子**（刚体） |
| 速度 / 惯性 | 有 `v <- wv + c1r1(p-x) + c2r2(g-x)` | 无标准速度方程，用概率选算子 | 无 |
| 个体历史最优 pbest | 有 | `PSO_BestEver*dist1`（指纹距离） | **无**，只有当代 `g` |
| 全局最优 gbest | 有 | `PSO_BestStruc*dist2` | 有，但取 `ranking[0]`（当代，可能 stale） |
| 随机性来源 | `c1 r1`, `c2 r2` | `rand` 概率 + 软模位移 | `U(0, step)` + 随机刚体旋转 |
| 分子完整性 | 不适用 | **不保证**（逐原子） | **保证**（刚体变换） |
| 晶胞变化 | 不适用 | 逐原子放置隐含可变 | **不变** |

所以严格说它不是 PSO，更接近「带引导的局部扰动 / (1+1)-ES 式收缩 + 取向噪声」，
或「父代与当代最优之间的逐分子随机插值」。

## 5. 对分子晶体有效吗

### 5.1 成立的部分

1. **不撕分子**：全部刚体变换，分子内几何逐位不变；比 MATLAB 原子级 PSO 适合
   分子晶体。
2. **周期性处理正确**：`_min_image` 用 `np.round` 半偶舍入，与 `newMolCheck` 口径一致；且已先把 `g` 按 `best.LATTICE` 对齐到 child 晶胞（§5.2 B 已修），不再混用两个参考系。
3. **有合法性门**：`valid_molecules(child, -0.2)` + 50 次重试 + 回退 Random，
   不会把原子重叠的结构放进种群。
4. **零风险默认态**：默认关闭 + 额外配额，不打开就完全不改变现有算子行为。

### 5.2 实质弱点（B 最严重；A 为健壮性隐患）

**A. 按位置索引配对，类型是对齐的，但只是隐式约定、且同类型内非最优匹配。**
（此条在初次评估中被误判为「会跨类型错配」，核实后更正。）
`SwarmMutation_310.py:103-116` 只比较分子**总数**（现已另外读 `MtypeLIST` 做断言），按
`enumerate` 的位置索引配对。但当前代码里这**不会**跨类型错配：
`GetPOP_MOL`（`src/GetPOP_MOL.py:8-12`）生成 `[1]*n1 + [2]*n2 + ...` 的分组列表，
`finalize_offspring → recompute_types`（`variation_common.py:63-67`）对每个子代重建
它，`heredity_molecule.py:125-185` 也按 `for ind in 1..n_types` 分组构造
`mol_table`，`Permutation_310.py:1-11` 明确只交换分子**位置**（平移）而保持
`MOLECULES`/`MtypeLIST` 顺序一致。实测 `ct22/results3/generation3` 的 106 个个体
`MtypeLIST` 全部是 `(1,1,2,2)`。于是位置 0/1 恒为 TNT、2/3 恒为 CL20，两侧类型
一致。**当时的两点隐患**：(1) 没断言这个不变量，一旦有算子重排 `MOLECULES` 条目、
或读入旧 checkpoint / 变组分运行，就会静默错配；(2) 同类型的多个分子**可交换**，
第 0 个 TNT 与最优的第 0 个 TNT 未必是同一个堆积位点，按索引硬配不是最优匹配
（assignment），可能给出绕远路的引导方向。后果是引导质量下降，**不是**撕分子或
类型错配；单组分体系（分子全同、不可分辨）下按索引配对完全没问题。
(1) 已补 `MtypeLIST` 一致性 `assert`（`:105-112`）：两侧类型序列不一致即抛
`AssertionError`，由 `EA_310` 的 `try/except` 兜底回退 Random 并打印原因，不再
静默错配；`(2)` 的最优匹配仍属可选优化，未做。

**B. 晶胞坐标系不对齐（最严重，且实测普遍存在；现已修复）。** 修复前 `targets` 是
`best` 的**笛卡尔**质心，但最小镜像折叠用的是 **child 的 `LATTICE`**（旧 `:76, :81`）——
一个混合了两个参考系的位移向量。heredity 会混合双亲晶胞
（`heredity_molecule.py:186-203`）、latmutation 会改晶胞；实测
`ct22/results3/generation3` 106 个个体的晶胞体积 min 1168 / max 1868 Å³，
**80 个不同值**，所以这不是罕见边界情况。

数值例子（对角晶胞，只看 x）：`best` 晶胞 a=10、分子质心 x=8 Å（分数 0.8）；
`child` 晶胞 a=12、分子质心 x=2 Å。

| 做法 | 计算 | delta | 新位置（child 分数） |
|---|---|---|---|
| 修复前 `:81` | `_min_image(8-2, child_L)` | **+6.0** | 8.0（0.667） |
| 正确 | 先把 8 Å 转成分数 0.8，映射到 child 晶胞得 9.6 Å，再折叠 | **−4.4** | −2.4 ≡ 9.6（0.8） |

方向甚至相反：修复前把分子拉到 child 晶胞的 0.667 处，而 `best` 的分子其实在
0.8 处。严格做法：`g_frac = g @ inv(best.LATTICE)`，`g_in_child = g_frac @
child.LATTICE`，再 `delta = min_image(g_in_child - center, child.LATTICE)`。

**修复**：`_min_image(target, center, lattice, target_lattice)` 新增
`target_lattice` 参数，在函数内完成上述分数坐标映射；`SwarmMutation_310` 始终
传入 `best.LATTICE`。不传时保持旧的单参考系行为（旧行为恰好是上表「当前」一列，
`tests/test_swarm_310.py::test_min_image_aligns_best_cell_into_child_frame` 同时
断言了 +6.0 与修复后的 −4.4）。端到端用例断言子代质心落在 0.9 Å 而非 3.5 Å。

**C. 位置与取向相互打架。** 质心朝 `g` 收缩（ exploitation），但每个分子又被叠加
一个**独立随机** ±30° 刚体旋转（`:85-87`），且该角度与 `g` 的取向无关。分子晶体的
堆积 motif 主要由**取向**决定（氢键方向、π–π 堆积）；「位置向最优学、取向随机化」
等于把 `g` 里最有价值的那部分信息破坏掉。这不是 PSO，更像给插值结果加噪声。

**D. 纯 exploitation，容易早熟。** 没有速度 / 惯性 / pbest，`U(0, 0.5)` 只收缩不
外推；在 CSP 的多漏斗地形上，子代被拉向当代最优附近，配合强精英保留
（`KeepBestStructures`）会进一步压缩多样性。`ranking[0]` 又是当代最优而非 ever-best，
引导信号本身噪声大（`valid_ranking` 注释自述 ranking 可能 stale）。

**E. 晶胞自由度完全没被探索。** 晶型搜索里体积 / 形状是核心变量，swarm 原样继承
父代晶胞。它只能在给定晶胞内重排分子，对「找到新晶型」贡献有限。

**F. 与已有算子增量重叠。** rotmutation 已做主轴刚体旋转 + 平移 + 呼吸晶格；
heredity 做双亲切片重组；精英保留已隐式提供「朝好结构靠拢」的选择压力。swarm
新增的信息主要就是「朝 `ranking[0]` 插值」这一项，边际收益不大。

**G. 没有验收判据。** 产出的子代只通过了距离合法性检查，没有任何「是否真的更像
`g`」或「适应度是否改善」的验收；很可能只是又一个合法的随机扰动。

### 5.3 结论

- **作为「保分子的局部精修 / 开发算子」**：设计合理、结构安全，可作为 rotmutation
  的补充，尤其适合单组分、已接近收敛的后期。
- **作为「PSO 全局搜索算子」**：方法上偏弱 —— 缺 pbest / 速度、晶胞不变、取向
  随机化与位置引导矛盾，不太可能显著提升全局搜索能力。
- **B（晶胞对齐）已修**，A 的 `MtypeLIST` 一致性断言也已补；两者均有回归单测。
  剩余 C~G 仍属方法层面弱点，不影响正确性。
- 默认关闭 + 额外配额 + 失败回退 Random，意味着工程风险低；现有
  `tests/test_swarm_310.py` 覆盖 `_min_image` / 断言 / 端到端位移，但仍
  **无实际运行数据，有效性未经实证**。
